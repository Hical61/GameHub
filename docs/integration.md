# 接入自己的项目

先运行公共演示确认构建、数据库和交付流程，再通过独立宿主登记自己的实现。公开项目不需要使用方的游戏源码、数据库表或本地目录即可编译和运行演示；真实渠道和权威发奖事务由使用方实现。

## 先跑通公共流程

按[README](../README.md)准备固定公开依赖、构建服务，初始化独立 Hub 数据库并设置运行密钥。演示接收端把合成流水和去重记录放在同一 SQLite 事务中，适合联调确认丢响应及重试行为，不连接已有玩家库。

公共演示使用 `demo-hmac-v1`。回调字段、签名、任务及业务 ACK 格式见[接口契约](api.md)。使用自己的游戏之前，先验证同身份重复通知不重复记账，同身份改内容返回冲突。

## 构建独立宿主

[examples/custom-host](../examples/custom-host/README.md) 是完整可编译的宿主，包含自己的入口、工厂注册、合成规则和配置。它复用公共 HMAC 演示实现，登记新的游戏与渠道类型，不修改默认工厂。

这个示例可直接在公开源码中构建，也可复制到自己的工程，通过 `GAMEHUB_SOURCE_DIR` 指向固定版本的公开源码。它链接 `GameHub::service` 和 `GameHub::bootstrap`，再构造 `Application(config, registry)`；临时工厂目录销毁后，注册表及适配器仍独立持有配置。

独立宿主使用 C++20。旧引擎或其他语言可以通过 HTTP 接收端、独立接入桥连接，不必把公共 C++ 库链接进游戏进程。

| 构建选项 | 独立构建默认 | 被宿主引入时默认 |
| --- | --- | --- |
| GAMEHUB_BUILD_APP | ON | OFF |
| GAMEHUB_BUILD_TESTS | ON | OFF |
| GAMEHUB_ENABLE_INSTALL | ON | OFF |

使用方可以显式覆盖选项。默认服务安装要求启用默认可执行程序；宿主自行决定安装自己的程序和协议实现。

## 实现渠道与游戏通信

| 扩展点 | 实现内容 |
| --- | --- |
| ChannelAdapter::parseCallback | 原始请求验签、渠道状态判断、字段检查、业务身份及规范化事件 |
| ChannelAdapter::reply | 把持久受理结果或固定错误类别编码为该渠道要求的应答 |
| GameAdapter::signOutbound | 游戏服请求签名 |
| GameAdapter::verifyInternalRequest | 配置拉取与应用回报的内部认证 |
| AdapterCatalog | 注册游戏工厂、游戏规则和渠道工厂，启动时校验配置并组装注册表 |

`CallbackRequest` 的 body、路径和请求头视图只在解析期间有效，返回的 `Submission` 要拥有自己的内容。同步回调解析不得阻塞等待远程服务；需要远程验单或证书更新时，应先明确异步接入和可信缓存办法。

规范化身份需要说明订单唯一范围。多商户可以使用独立 namespace；重试、人工处理及备份恢复都沿用同一身份。商品、金额、币种、角色归属和区服映射由实际游戏规则验证，演示规则不代表正式渠道协议。

当前 Worker 使用统一 JSON POST 和 `taskId/committed` 业务确认。仅更换签名适配器不会改变通信封装；异构游戏可在自己的接收桥转换协议，确需修改统一契约时，应同时修改接口与兼容性测试。

## 完成游戏权威事务

接收端先校验签名、游戏、区服和契约版本，然后以 `(gameId, serverId, taskType, namespace, bizKey)` 持久化去重。同身份异内容应拒绝，不能重复产生经济效果。

去重记录、经济修改及权威流水必须具有同一提交边界。游戏采用 Lua、玩家内存、数据库进程或存储过程时，要沿实际链路确认最终提交，而不是把“进入队列”或“发送成功”当成 committed。

业务已经提交但 ACK 丢失时，重复请求应查询并返回原结果。离线、退出、重启和跨服移动都要有明确的持久化与缓存同步路径。退款、撤销等业务需要自己的状态模型，不通过另建充值身份自动补偿。

配置接收端还需完成启动补拉、内容摘要检查、原子应用、当前版本持久化、乱序保护和应用回报。公共演示接收端提供合成实现，实际配置应用逻辑仍归游戏所有。

## 公开与本地内容

公开目录保留通用接口、框架、演示协议、合成测试和文档。真实协议、专用适配器、数据库结构、业务规则、运行配置和备份可以放到根目录 `private/`，该目录被 Git 忽略且发布检查拒绝收录。也可以在独立私有仓库维护宿主，引用固定版本的公开 GameHub。

默认 CMake、默认工厂、CI 和安装规则不会扫描或引用本地私有目录。公共文档使用可运行的合成示例，不要求读取维护者的真实游戏项目。

## 验证接入

至少覆盖重复与并发通知、同身份冲突、业务回滚、提交后丢 ACK、接收端重启、旧租约迟到、人工重排、配置乱序、权限和密钥轮换。负载按广播展开后的任务量估算，再验证真实目标的延迟、积压与恢复时间。

可用以下命令导出当前工作区的公开候选，复制结果不含私有目录或构建产物：

```powershell
python scripts/check-public-source.py
```

导出器同时包含尚未提交但可公开的新文件，便于提交前验证。实际构建应在输出副本中执行，公开第三方依赖通过正常 CMake 参数提供；不要从原工作区补入缺失的专用文件来让检查通过。
